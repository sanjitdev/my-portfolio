# Story: 015-seo

## User Story

**As a** recruiter or visitor sharing the portfolio
**I want** the site to have proper meta tags, Open Graph data, sitemap, and favicon
**So that** it looks polished when shared on LinkedIn/Twitter and ranks well in search engines

## Acceptance Criteria

- [ ] **Given** I view page source, **When** I check the `<head>`, **Then** `<title>` contains the candidate's name and title
- [ ] **Given** I view page source, **When** I check meta tags, **Then** `<meta name="description">` contains the candidate's summary (truncated to ~155 chars)
- [ ] **Given** I view page source, **When** I check Open Graph tags, **Then** `og:title`, `og:description`, `og:type`, `og:url` are present
- [ ] **Given** I share the URL on LinkedIn, **When** the preview is generated, **Then** it shows the name, title, and summary
- [ ] **Given** I share the URL on Twitter, **When** the preview is generated, **Then** Twitter Card tags (`twitter:card`, `twitter:title`, `twitter:description`) are present
- [ ] **Given** I visit `/sitemap.xml`, **When** the page loads, **Then** it returns a valid XML sitemap
- [ ] **Given** I visit `/robots.txt`, **When** the page loads, **Then** it allows crawling and references the sitemap
- [ ] **Given** I view the site, **When** the favicon loads, **Then** it appears in the browser tab (no 404 in the network tab)
- [ ] **Given** I run Lighthouse SEO audit, **When** it completes, **Then** the score is ≥ 95
- [ ] **Given** I view the page on mobile, **When** I check meta tags, **Then** `<meta name="viewport" content="width=device-width, initial-scale=1">` is present

## Technical Notes

- Use Next.js's Metadata API in `app/layout.tsx`:
  ```ts
  export const metadata: Metadata = {
    title: `${personalInfo.name} – ${personalInfo.current_title}`,
    description: personalInfo.summary.slice(0, 155),
    openGraph: {
      type: 'website',
      title: `${personalInfo.name} – ${personalInfo.current_title}`,
      description: personalInfo.summary.slice(0, 155),
      url: 'https://{deployment-url}',
    },
    twitter: {
      card: 'summary',
      title: `${personalInfo.name} – ${personalInfo.current_title}`,
      description: personalInfo.summary.slice(0, 155),
    },
  }
  ```
- Sitemap: use Next.js's built-in `app/sitemap.ts`:
  ```ts
  export default function sitemap() {
    return [{
      url: 'https://{deployment-url}',
      lastModified: new Date(),
      changeFrequency: 'monthly',
      priority: 1,
    }]
  }
  ```
- Robots: `app/robots.ts`:
  ```ts
  export default function robots() {
    return {
      rules: { userAgent: '*', allow: '/' },
      sitemap: 'https://{deployment-url}/sitemap.xml',
    }
  }
  ```
- Favicon: place `app/favicon.ico` (or use Next.js's `app/icon.tsx` for a generated one)
- Deployment URL: use a constant or env var (`NEXT_PUBLIC_SITE_URL`); default to `https://{project-name}.vercel.app` for v1

## Edge Cases

| Scenario | Expected Behavior |
|----------|-------------------|
| `NEXT_PUBLIC_SITE_URL` env var not set | Default to `https://sanjit-majumdar.vercel.app` (or warn at build) |
| Summary is exactly 155 chars | Truncate at 152 + "..." for safety |
| Very long name in title | Browsers handle this; no truncation needed |
| Custom domain added later | Update env var; rebuild |

## Out of Scope

- Structured data (JSON-LD for `Person` schema) — nice to have, not in v1
- Multi-page sitemap (single-page site doesn't need it)
- Image-based OG cards (would require a design asset; text-only OG is fine)
